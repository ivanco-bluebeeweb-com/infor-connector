# Infor Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: интеграционный
инженер или ops-администратор, впервые открывающий приложение.

## 1. Credential type
ION API Gateway service-account credentials — либо целиком вставленный `.ionapi` JSON
(из ION Desk), либо отдельные поля (tenant id, client id/secret, portal URL, service
account access/secret key) для случаев, когда файл недоступен целиком.

## 2. Идеальный флоу (без ограничений SDK)
1. **Явное объяснение природы коннектора при первом открытии** — простыми словами:
   это не типизированный коннектор к конкретному продукту (LN/M3/SunSystems), а
   универсальный аутентифицированный мост к ION API Gateway — пользователь сам
   указывает, какой путь (endpoint) вызывать.
2. **Два способа подключения** — (а) вставить весь `.ionapi` файл одним полем
   (самый быстрый путь для пользователей с доступом к ION Desk), (б) заполнить поля
   по отдельности вручную.
3. **После успеха** — сразу попытка вызвать несколько типичных ION-путей (health/ping
   эндпоинты, если Infor их документирует) чтобы показать, что подключение реально
   работает, а не просто прошло OAuth-рукопожатие.
4. **Явное предупреждение о партнёрской документации** — если вызов конкретного
   пути возвращает 404/403, явно объяснить, что этот путь может требовать документации,
   доступной только через партнёрский портал Infor, а не считать это неизвестной
   ошибкой.
5. **ION Workflow / Document Flow как второй уровень** — после базового подключения,
   отдельная вкладка с списком задач workflow и статусов document flow сообщений —
   уже готовые, типизированные списки поверх универсального моста.
6. **Multi-tenant** — если у интегратора несколько ION-тенантов (dev/test/prod),
   явный переключатель между сохранёнными подключениями.

## 3. Разница с реализацией сейчас
См. `UI_COMPONENT_PLAN.md` §0 — реализация ограничена явным, введённым пользователем
ION-путём для generic-вызовов; не предполагает автоматического обнаружения доступных
путей, которое потребовало бы закрытой партнёрской документации.
