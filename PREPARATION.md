# Infor Connector — Preparation

**Version:** 0.1.0 (planning)
**Date:** 2026-08-24
**Related task:** BBW Imperal Apps #2410
**Scope decision:** maximum feasible capability against the publicly documented
Infor OS / ION API Gateway surface (per standing "максимальный функционал" instruction,
bounded honestly by what Infor documents outside its partner portal — see
CONNECTOR_DISCOVERY.md §4).

## 1. App passport

**Name:** Infor Connector (ION API Gateway)
**One-line purpose:** Connect your own Infor OS tenant via ION API Gateway OAuth2
credentials to call any ION-routed REST endpoint across your licensed Infor CloudSuite
products (LN, M3, SunSystems, and others), plus manage ION Workflow-visible items and
Document Flow messages.

**What it is not:**
- Not a per-product connector with typed Vendor/Customer/PO schemas for LN, M3, or
  SunSystems individually — those schemas differ per product and per customer
  configuration, and Infor's detailed per-product OpenAPI specs sit behind its partner
  portal. Instead this connector exposes a **generic, capability-aware REST bridge**
  through ION, mirroring the honest pattern used for SAP OData generic passthrough,
  but at the ION Gateway layer.
- Does not assume any specific IONAPI path exists on a tenant — every call is made
  explicit by the caller (full IONAPI path) and every response is returned as-is.

## 2. Human problem

> An integration engineer or ops analyst at a company running Infor CloudSuite
> (any vertical) needs a lightweight way to call their tenant's ION API endpoints,
> check ION Workflow tasks, and inspect Document Flow message status — without
> writing custom OAuth2 + IONAPI-file boilerplate themselves.

### Personas
| Persona | Trigger | Value |
|---|---|---|
| Integration engineer | Needs to call a specific ION-routed endpoint | Generic authenticated REST call, no custom OAuth code |
| Ops/workflow admin | Needs to see pending ION Workflow tasks | List/read/act on workflow tasks |
| Integration support | Needs to debug a stuck Document Flow message | List/inspect Document Flow message status |

## 3. Credential model

ION API Gateway service-account credentials, as generated by ION Desk into an
`.ionapi` file: `ti` (tenant id), `cn`/`cs` (OAuth client id/secret), `pu` (portal/token
URL base), `saak`/`sask` (service account access/secret key) — connect form accepts
either pasting the raw `.ionapi` JSON content, or the individual fields separately for
tenants that only share individual values.

## 4. Tiered capability plan

**Tier 1 (core, always attempted):**
- connect_infor / disconnect_infor / list_connections
- call_ion_api (generic authenticated REST call to any ION-routed path — GET/POST/PUT/DELETE)
- audit_infor_access (probe a caller-supplied list of common ION paths, report which respond)

**Tier 2 (ION Workflow):**
- list_ion_workflow_tasks / get_ion_workflow_task / action_ion_workflow_task (approve/reject/complete)

**Tier 3 (ION Document Flow):**
- list_document_flow_messages / get_document_flow_message / resend_document_flow_message

Every tool is explicit about the exact ION path/document ID it touches; nothing
guesses at a schema Infor has not published outside its partner portal.
